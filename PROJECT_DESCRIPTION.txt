================================================================================
                        ЛОГИКА РАБОТЫ ПРИЛОЖЕНИЯ
================================================================================

ПРОЦЕСС АВТОРИЗАЦИИ:
1. Пользователь вводит Email и Пароль
2. Пароль хешируется через HashPassword.HashPassword()
3. Поиск в таблице UserAuthorization по Email и HashPassword
4. Со второй попытки появляется капча
5. После 3 неудачных попыток - блокировка на 12 секунд
6. При успешном входе определяется роль:
   - Если есть запись в Employees с PositionID = 1 → Администратор → EmployeesPage
   - Если есть запись в Employees с другим PositionID → Сотрудник → Client (с проверкой рабочего времени)
   - Если нет записи в Employees → Клиент → Client
7. Гость может войти без авторизации

УПРАВЛЕНИЕ СОТРУДНИКАМИ (только администратор):
1. Просмотр списка всех сотрудников (ListView)
2. Поиск по ФИО (TextBox)
3. Фильтрация по должности (ComboBox)
4. Добавление нового сотрудника:
   - Ввод ФИО, телефона, должности
   - Создание учетной записи (Email + Пароль)
   - Валидация всех полей
   - Хеширование пароля
   - Сохранение в БД (UserAuthorization + Employees)
5. Редактирование сотрудника (двойной клик):
   - Изменение данных
   - Опциональное изменение пароля
   - Валидация и сохранение
6. Удаление сотрудника

БЕЗОПАСНОСТЬ:
- Пароли хешируются SHA256
- Капча после первой неудачной попытки
- Блокировка после 3 неудачных попыток
- Проверка рабочего времени для сотрудников
- Проверка прав доступа (только администратор может управлять сотрудниками)

ВАЛИДАЦИЯ ДАННЫХ:
- Email: обязательное поле, формат email, макс 100 символов
- Пароль: обязательное поле, минимум 6 символов
- Фамилия/Имя: обязательные поля, 2-50 символов
- Отчество: необязательное, макс 50 символов
- Телефон: формат телефона, макс 20 символов
- Должность: обязательное поле
